# R1 live incident — naked OKX leg (2026-11-10)

## What happened

1. `arbtwin-rwa-live` was armed live (`dry_run=False`) with CRCL only, $15 cap, $14 floor.
2. During a later entry window the OKX post-only buy filled (0.2 CRCL) while the Lighter
   sell leg did not complete: first `20558 restricted jurisdiction` (China egress), then
   repeated `orderBookDetails/orderBookOrders` timeouts after the KL proxy was added.
3. The round sat in `ENTRY_PARTIAL` with a long OKX leg and no Lighter hedge.
4. Market-data REST calls kept timing out (`OKX books` and Lighter REST), so the engine's
   abort/unwind path could not price or place the reduce-only order.
5. Manual intervention: stopped the service, sold 0.2 CRCL reduce-only IOC at 65.77.
   Positions are now flat.

## Root causes

- **Leg-first asymmetry is not enforced**: both legs are quoted post-only; OKX can fill
  while Lighter fails, and `ENTRY_PARTIAL` depends on live books to abort.
- **Single proxy for both venues**: `ARBTWIN_PROXY` pointed at the LA proxy; Lighter data
  through it is slow/blocked, while Lighter orders need the KL proxy. REST timeouts then
  disabled the abort path.
- **No data-outage flatten**: when books are unavailable, `wave_step` skips the symbol
  instead of flattening a known naked leg with a collared IOC.

## Fixes required before re-arming

1. Separate venue proxies: OKX via LA (`3128`), Lighter via KL (`3129`) for **both** data
   and orders.
2. On `ENTRY_PARTIAL`, if either book is unavailable for > N seconds, send a collared
   reduce-only IOC for the filled leg using the last known price; never wait on a book.
3. Place the Lighter leg first and require an accepted order id before sending OKX; or
   send OKX as IOC only after Lighter confirms a fill.
4. Persist `rounds.jsonl` recovery so a restart cannot re-open the same symbol on top of
   an orphan.
5. Keep the kill switch file checked every loop.

**Current state: service stopped, both venues flat, no open orders.**
